# 后台精简与上传限制修复计划

日期：2026-11-06　状态：已实施；验证与清理清单见 [实施记录](admin-cleanup-status.md)

以当前 `RelayView.vue` 首页已经提供的功能为产品边界：配对与审批、记住浏览器、重新配对、多文件独立上传、续传、共享列表、下载和删除。此次精简管理后台，同步清理废弃功能的代码、数据库结构和数据，并修复与保留功能直接相关的配置，不扩展前台业务。

本文是对 `docs/plan.md` v1.3 的后续调整建议。原计划中的配对、权限、24 小时保留、首次完整下载后 10 分钟重试窗口、租约和清理规则继续沿用；后台范围和容量配置按本文实施。本轮已完成应用修改和数据库迁移，实际验证及边界以实施记录为准。

## 1. 核查结论

### 1.1 单文件限制失效的原因已确认

| 环节 | 当前实现 | 问题 |
| --- | --- | --- |
| 后台设置 | `useSystemConfig.ts` 提交 `upload_size`，`ConfigService` 写入数据库并刷新运行配置 | 保存本身能成功 |
| 前台预检 | `useRelay.ts` 在选择文件和重试时写死 `1_000_000_000` | 不读取后台值 |
| 服务端上传 | `UploadInput.size` 使用 `Field(le=config.MAX_FILE)`，`MAX_FILE` 固定为 1 GB | 不读取后台值；模型声明时绑定的常量也不能实现动态调整 |
| 全站容量 | `start_upload()` 使用固定 `MAX_STORAGE = 500_000_000_000` | 后台的 `storage_limit` 同样不控制新上传流程 |
| 概览和公开配置 | 同时存在旧配置值与 Relay 固定值；后台表单按 1024 换算，首页按 1000 展示 | 同一页面可能显示与实际执行不同的规则 |

已使用真实 ASGI 接口链、内存数据库和临时文件目录复现：初始化 → 管理员登录 → 保存 `upload_size=10,485,760` → 回读确认 → 首页设备配对 → 分片上传并发布 `11,534,336` 字节文件。上传成功，超过已保存上限。未访问或修改正式数据库、文件及 NAS。

### 1.2 后台仍混有旧产品功能

- 路由保留 NAS 本地文件和 MCP 页面。MCP 虽不在侧栏，仍有前端路由；旧公开 MCP API 已在 `main.py` 关闭。
- 设置仍包含外部存储、主题选择、提取码生成、保存模式、旧上传和错误限流等选项；其中多项没有接入 Relay。
- 文件管理仍保留提取码、文本分享、备注标签、视图预设、健康建议和过期策略编辑等复杂功能。
- Relay 文件的过期时间和策略编辑已被服务端拒绝，但后台仍保留相关操作体系，造成无效入口。
- 概览仍有文本占比、永久文件、旧上传开关与保存期限等展示，不能准确表达当前临时文件中转规则。

## 2. 后台目标：三个入口

### 2.1 概览

保留用于判断系统是否能继续接力的必要信息：

- 当前有效文件数、等待清理文件数。
- 全站容量上限、已发布文件占用、上传预留及残留分片占用、剩余额度。
- 数据目录所在磁盘的可用空间，与应用额度分别展示。
- 当前单文件上限、上传开放状态。
- 固定保留规则：最多 24 小时，首次完整下载后 10 分钟。
- 运行时长和版本信息。

移除文件类型占比、健康评分和建议卡片、永久文件统计、昨日对比、累计领取指标、按旧单文件上限计算的今日容量进度。无需新建独立活动日志页面；保留必要的服务端操作记录，精简面向旧功能的记录逻辑。

所有限制和容量数字必须来自实际执行上传校验的同一策略与容量计算服务，不再在前端补写 500 GB 等默认业务值。数据加载失败显示错误和重试，不伪装成 0 或“正常”。

### 2.2 文件管理

保留一个简明列表：

| 内容 | 处理 |
| --- | --- |
| 文件名、大小、上传时间、首次完整发送时间、有效截止时间 | 保留；截止时间使用 Relay 实际字段 |
| 状态 | 统一为待领取、重试窗口中、已到期、等待清理、清理失败；下载中的租约保护可显示为附加提示 |
| 查找与列表操作 | 文件名搜索、状态筛选、分页、上传时间排序、刷新 |
| 查看详情 | 只读展示上述信息，必要时补充 SHA256 和清理错误摘要 |
| 下载 | 保留管理员下载，沿用当前会触发首次完整发送计时的行为；按钮附近说明影响 |
| 删除 | 保留单项和批量删除，沿用待删状态、租约保护、实体清理成功后释放容量 |
| 提取码、提取码链接和二维码 | 移除；内部 UUID 不能当作配对口令展示 |
| 修改文件名、过期时间、下载次数，延长 24 小时/7 天、永久保存 | 移除入口和对应可调用接口 |
| 文本分享与文本预览/导出 | 移除 |
| 备注、标签、视图预设、复杂健康筛选、策略时间线 | 移除页面、专用接口和无引用逻辑 |

列表状态、下载资格和删除资格复用 Relay 生命周期判断，不能继续只依赖旧的 `expired_count` 或健康建议引擎。配对口令、设备凭证、会话哈希不进入管理员文件列表。

管理员下载是否应改变计时是独立产品问题，本轮沿用当前代码，避免在后台精简中另改下载规则。

### 2.3 系统设置

仅保留与当前产品实际关联的设置：

| 分类 | 保留内容 | 实施要求 |
| --- | --- | --- |
| 站点 | 站点名称/页面标题、简介、通知标题和内容、首页管理入口显示开关 | 对应实际页面标题、通知及入口；统一硬编码与配置的使用位置 |
| 管理员 | 修改密码、登录有效天数 | 保留现有密码哈希和修改密码后令牌失效机制 |
| 上传与容量 | 开放上传、单文件上限、全站容量上限 | 全部接入 Relay，保存成功即成为服务端执行值 |
| 只读说明 | 本地磁盘存储、数据目录、24 小时和 10 分钟规则 | 说明实际值，数据目录通过部署环境管理 |

移除以下编辑区和配置写入能力：

- NAS 本地文件浏览/分享/原文件删除，以及对应后台页面、路由和 API。
- MCP 页面、路由、令牌设置和相关前端代码。
- S3、WebDAV、OneDrive、OpenDAL 等外部存储选择和凭证设置。
- 存储路径编辑、分片启用开关；Relay 使用既定数据目录，按文件大小自动选择上传方式。
- 提取码类型、逐文件保存模式、永久/次数到期、最大保存时间。
- 文件类型白名单、旧上传频率和错误次数设置；本轮保持当前首页支持任意文件类型及现有实际防护规则。
- 主题切换、SEO 关键词、robots 编辑等非必要选项；固定使用当前主题，保留深浅色和语言能力。

保留服务端正在使用的配对和管理员登录限流、CSRF/来源校验、设备和管理员认证隔离；不因移除设置项而关闭这些保护。若未来需要管理这些参数，另行设计实际生效的配置。

## 3. 上传与容量的统一规则

以下为本轮建议采用的具体规则，不将其冒充此前已确认的决定。

### 3.1 单一配置来源与单位

1. 复用 `settings.upload_size` 和 `settings.storage_limit`，作为运行时唯一配置来源。Relay 常量仅保留默认值和产品边界，不再作为与后台并行的执行配置。
2. 建议新安装默认单文件 1 GB、全站 500 GB；本轮允许后台在这两个既有产品上限以内调低，超出范围返回明确错误。提高产品上限另行调整。
3. 两项限制必须为正整数个字节；0 不表示无限。零字节文件仍允许上传。布尔值、负数、无穷值和不能精确转为字节的输入一律拒绝。
4. 新界面统一使用十进制 KB/MB/GB：1 MB = 1,000,000 字节，1 GB = 1,000,000,000 字节。设置、文件大小、错误提示和概览保持一致。
5. 已保存的正整数字节值原样保留，不能因为更改单位而放大、缩小或四舍五入。旧表单“10 MB”存下的 10,485,760 字节应精确回显；未编辑该字段时保存其他设置不得改变它。
6. 存量 `storage_limit=0` 在有版本标记的一次性配置升级中转成原 Relay 实际使用的 500 GB；缺失值补默认，合法已保存的单文件限制包括 10 MB 应被尊重。无效或越过本轮边界的存量值需有明确修正规则及日志，采用保守限值，不默默解释成无限。转换幂等，重启不重置用户设置。

### 3.2 服务端强制执行

- 抽取统一的 Relay 上传策略读取与校验函数，供上传、公开配置、后台配置和概览使用。
- `UploadInput` 保留严格的结构和非负大小校验，将实际大小上限校验移入请求处理阶段，读取最新设置。
- 新建上传会话必须先验证开放状态、单文件上限，再做容量预留和磁盘余量判断；超限返回 HTTP 413 和明确上限，不创建会话、分片目录或容量预留。容量不足继续返回 HTTP 507。
- 普通上传、分片写入、恢复未完成会话、重试、合并及最终发布均执行适用的最新规则。不能通过旧 upload ID 或客户端伪造大小绕过限制。
- 保留每片实际长度、总长度、完整 SHA256 校验；不能只检查 `Content-Length` 或客户端声明。
- 发布前在状态协调锁内重新检查当前配置；配置保存与最终发布有明确先后顺序，避免正在合并的文件越过已生效的新限制。
- 开放上传开关接入新流程；关闭后拒绝新会话及未完成上传的后续写入/发布，仍允许查询状态与取消。重新开放后允许仍有效、未取消且符合当前限制的会话继续。

### 3.3 修改设置时的行为

| 场景 | 建议行为 |
| --- | --- |
| 调低单文件上限 | 新上传立即按新值校验；未完成且超限的会话后续操作被拒绝，标记取消并交由现有清理流程回收 |
| 调高单文件上限 | 新上传、待上传项和失败重试按新值处理；不超过本轮产品上限 |
| 已经发布的大文件 | 不追溯删除，继续按原截止时间下载与清理 |
| 已完成会话重复 complete | 返回原结果，保持幂等，不因降低上限把已完成文件变成失败 |
| 调低全站上限至当前占用以下 | 可以保存；显示已超额并拒绝新增容量预留，保留现有文件和已合法预留的上传 |
| 已有上传继续分片或发布 | 不重复预留容量；调低总额度不单独撤销已有合法预留，单文件限制与开放开关仍按最新规则判断 |
| 取消/清理失败 | 释放额度前确认实体已删除；失败记录及相应容量继续追踪 |

配置变更通过现有持久化和强制刷新机制生效，无需重启。统一协调锁的获取顺序，避免配置保存、上传、发布和清理之间死锁。

### 3.4 前台只做必要适配

- 从公开配置接口取得有效的 `upload_size`、`open_upload`，同步类型和状态管理，删除首页和重试逻辑中的 1 GB 硬编码。
- 页面加载、恢复前台、开始处理上传队列和手动重试前刷新策略。取不到配置时显示可重试的错误，避免回退到写死上限继续上传。
- 选择、拖放和粘贴共用大小预检；超限项直接给出实际限制，在完整 SHA256 计算和传输前停止。
- 上传区显示当前上限及暂停状态，不增加新的业务板块。
- 已打开页面即便暂未刷新，也必须被服务端正确拦截；收到 413/暂停响应后更新策略并显示原因，不自动重试死循环。
- 设置更新不改变配对凭证，不清空成功队列、共享列表或其他设备状态。

## 4. 精简要落实到代码与数据库

代码和数据库清理均为本轮必交付内容，不能只隐藏菜单、停用接口或保留整套废弃实现。

### 4.1 代码清理

1. 删除前端菜单、路由、页面及无引用的 composable、service、类型和文案；旧后台书签导向文件管理或概览，不继续加载被移除模块。
2. 移除 NAS 本地文件、文件策略编辑、备注标签、视图预设和文本预览等专用管理 API。移除的 API 返回 JSON 404/410，不能被 SPA 兜底成成功页面。
3. 管理员配置读取和更新改成明确的允许字段集合，停止整包透传旧配置、旧存储凭证和部署参数；只提交本次允许修改的字段。移除字段的写入应明确拒绝。
4. `/setup` 初始化页面、解析器、默认值、公开配置、前端缓存及 `/health` 同步收敛，不能在新安装、刷新或容器重建时再次产生另一套限制和旧能力声明。
5. 保留 `/share`、`/chunk`、`/presign`、`/api/presign`、`/mcp` 已关闭的协议边界；精简后台不能重新开放匿名上传。
6. 按引用关系删除废弃功能的服务方法、模型、后台任务、配置默认值、常量、依赖包和辅助逻辑。底层旧存储代码及公共组件确认无保留功能依赖后删除；仍在使用的部分先解除对废弃字段和服务的依赖。
7. 同步更新测试、接口契约、构建配置和文档，移除仅服务于废弃功能的内容；保留旧入口关闭、权限隔离、数据库升级及现有业务的回归覆盖。

### 4.2 数据库结构与废弃数据清理

1. 实施前建立清理清单，逐项列出废弃功能对应的 ORM 模型、表、字段、索引、外键、KeyValue 键和 JSON 配置项，以及代码引用与保留数据的对应关系。不能仅凭旧名称判断可删除。
2. 删除确认只服务于旧匿名上传、预签名上传、NAS 分享、文本分享、备注标签、视图预设、旧提取码及过期策略等废弃功能的表、字段和索引；清理对应废弃记录、旧配置及外部存储凭证。复用表和字段须先适配保留功能，再删除废弃部分。
3. 完整保留现有 Relay 文件记录和实体、配对组、设备及凭证、上传归属、仍有效的上传会话与分片记录、容量记账、下载租约、清理状态、管理员认证及必要操作记录。发布时间、首次完整发送时间和有效截止时间不得重置。
4. 对共用表及 KeyValue JSON 数据做定向迁移，只删除清单中的废弃结构和键；先完成第 3 节的有效配置转换，再删除旧键，不能整表清空或重建空数据库。
5. 使用新增的有版本登记的数据库迁移完成清理，不改写已执行的历史迁移编号。SQLite 删除字段、重建表等操作须正确复制保留数据、恢复必要约束和索引，并检查外键及数据完整性。
6. 迁移前完成一致性备份并记录恢复方法；涉及表结构的变更在应用接收业务请求前执行，避免与上传、下载和清理并发。迁移失败时停止启动并保留可恢复的备份，不带着部分升级状态继续服务。
7. 同时验证全新安装和现有 FileRelay 数据库升级。重复启动、迁移重试及容器重建不能重复删数据，也不能重新生成已废弃的表、字段和配置。历史迁移为升级链保留，不视为待删除的业务代码。
8. 本轮清理不删除仍需保留的文件实体或 NAS 挂载原文件；废弃文件记录如仍关联实体，必须先核实归属和用途，不能通过删库记录遗留无法追踪的实体，也不能绕过现有清理及容量释放规则。

## 6. 验收标准

### 6.1 上传限制与配置

- 通过管理员真实登录和配置 API 设置 10 MB（新单位为 10,000,000 字节），回读、公开配置、首页提示和概览完全一致。
